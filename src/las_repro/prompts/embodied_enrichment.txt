[semantic rules]
- Use only states directly supported by visible evidence in the fixed segment.
- For visible human hands, use left_hand, right_hand, or both_hands. Use gripper labels only for visible robot grippers, and robot_arm only when laterality is not visible.
- Handedness names the person's anatomical left or right_hand, never a side of the frame. Third-person cameras mirror the person, so an arm entering from the frame's right edge is often the person's LEFT arm. Judge from visible anatomy: thumb side, palm orientation, and how the arms cross. Keep each physical hand under one name for the whole video, and never label two simultaneously visible hands with the same name.
- Keep target names stable across adjacent segments.
- During transport, place, or release, target remains the manipulated object rather than the destination.
- Use none for an empty retracting or idle hand. Use unknown when visual evidence is insufficient.
- Skill meanings: move is repositioning along a supporting surface, including sliding or pushing a held object across a table; transport is lifting an object off its support and carrying it through the air; approach is closing distance before contact; contact is touching without securing a grip; stop is visible motion coming to rest, and also a hand holding an object steady without repositioning it.
- state_change is a transformation of the object's own state or configuration: opening, closing, deformation, tipping over, a stack or assembly collapsing, breaking. Gravity-driven and motion-filled transformations still count: a block tower toppling is state_change, not autonomous_motion, because the salient outcome is that the assembly is now in a different state.
- Use autonomous_motion when an object translates through space on its own with no visible hand or gripper contact and remains intact as one unchanged piece, such as a ball rolling, an object sliding, or falling; pair it with actor unknown.
- When both could apply, decide by the salient visible outcome: the object ends up somewhere else but unchanged is autonomous_motion; the object or assembly ends up in a different state or configuration is state_change.
- IMPORTANT: Choose skill based on the target object's physical relationship to its support surface, NOT by inferring from actor_state. A hand in actor_state=transporting may perform skill=move if the target object slides along the table without losing contact with the surface. Conversely, skill=transport requires the target to lift off and be carried through the air, regardless of actor_state. Example: "hand pushes board left across table" is skill=move even when actor_state=transporting; "hand lifts apple upward off table" is skill=transport.
- The occlusion_enter, occluded, and occlusion_exit values belong to the scene branch; do not use them for a manipulation segment.
- Do not infer intent, hidden controller state, contact, material, function, or motion that is not visible.
