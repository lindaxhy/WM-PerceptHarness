[rules]
- Proposed occluders and bounding-box overlap are inspection cues, not proof of occlusion. Require a visually supported disappearance behind an actual visible entity within the allowed interval.
- edge_departure=true favors out_of_frame unless direct visible evidence contradicts the edge-exit explanation and shows the same physical target pass behind an actual occluder.
- A track fragment is not a separate physical entity. Different tracks may describe the same visible object; never invent an unobserved tracked portion of a visible entity to explain detector loss as occlusion.
- Never choose an incorrect proposed entity ID merely to fit the contract. If the actual occluder or disappearance is unresolved, use unknown with no events rather than inventing an identity or event.
- classification is occlusion, out_of_frame, detector_loss, or unknown.
- Claim occlusion only when the video visibly supports the target passing behind a proposed occluder. A missing or low-confidence detection is not proof of occlusion.
- Copy candidate_id and target_entity_id exactly. occluder_entity_id must be one proposed entity ID or unknown.
- Only an occlusion classification may contain events. Otherwise events must be empty.
- An occlusion classification MUST contain at least one visibly supported event with positive duration using the candidate's allowed bounds. Occlusion with an empty events list is invalid. If no such interval is supported, use unknown with empty events; never fabricate an event to satisfy validation.
- event_type is occlusion_enter, occluded, or occlusion_exit. Each event contains exactly event_type, start, and end. start and end are numeric, must be copied from that candidate's allowed_start_times and allowed_end_times, and must have positive duration with start less than end. Do not substitute timestamp for either bound.
- Do not invent entities, timestamps, paths, masks, candidate fields, or evidence. Do not copy mask references or filesystem paths into the output.
- visual_evidence briefly describes only the visible basis for the classification. confidence is a finite number from 0.0 through 1.0.
- Within visual_evidence string values, use plain words: no forward slash, backslash, curly braces, square brackets, mask filenames ending in .mask, .npy or .npz, serialized mask rows, or control characters. This restriction also applies to ordinary slash punctuation: write "left or right" or "enter and exit" instead. JSON object syntax and the required events array are unaffected; do not copy these textual restrictions into output fields.
